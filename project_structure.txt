# 📊 Employee Productivity Analytics & Workforce Intelligence Web App

## 📌 Project Overview

The **Employee Productivity Analytics & Workforce Intelligence Web App** is an interactive data analytics application developed using **Python, Pandas, Machine Learning, Plotly, and Streamlit**.

The main objective of this project is to transform employee-related data into meaningful insights that can help organizations understand **employee productivity, engagement, performance, training, competency, and work-life balance**.

The application combines **data analysis, visualization, machine learning, anomaly detection, bias analysis, and scenario simulation** into a single interactive web application.

Instead of manually analyzing large amounts of employee data, HR professionals and managers can use the application to quickly identify workforce patterns, compare departments, identify employees with low productivity, analyze employee performance, and explore possible productivity improvements.

---

## 🎯 Problem Statement

Organizations collect large amounts of employee data, but raw data alone does not provide useful information for decision-making.

Managers may need answers to questions such as:

* What is the average employee productivity?
* Which departments have higher or lower productivity?
* Is employee training associated with productivity?
* Which employees have high engagement?
* Which employees have unusually low productivity?
* How are work-life balance scores distributed?
* How do employee training, engagement, and competency relate to performance?
* What could happen to productivity if training is increased or meetings are reduced?

This project addresses these questions by converting employee data into **visual insights, analytical results, machine learning predictions, and interactive simulations**.

---

# 🚀 Key Features

### 1. Productivity & Engagement KPIs

Displays important workforce metrics such as:

* Average Productivity Score
* Average Engagement Score

These KPIs provide a quick overview of the overall workforce.

### 2. Department Productivity Analysis

Compares average productivity across different departments using an interactive bar chart.

### 3. Training vs Productivity Analysis

Uses a bubble scatter plot to analyze the relationship between:

* Training Hours
* Productivity Score
* Competency Score
* Engagement Score

### 4. Employee Engagement Leaderboard

Displays the top 5 employees based on engagement score along with their productivity and department.

### 5. Work-Life Balance Analysis

Uses a histogram to understand the distribution of employee work-life balance scores across departments.

### 6. Productivity Anomaly Detection

Identifies employees whose productivity score falls below a predefined threshold.

In the current implementation:

```python
ProductivityScore < 65
```

is considered an anomaly.

### 7. Machine Learning Performance Classification

A Random Forest classification model is trained using:

* Training Hours
* Engagement Score
* Competency Score

to classify employees into different performance categories.

### 8. Bias Analysis

Compares model-generated scores across departments and performance categories to identify differences between groups.

### 9. Scenario Simulation

Allows users to interactively change:

* Meeting reduction percentage
* Training increase percentage

and observe the resulting simulated productivity.

### 10. Interactive Web Application

All analytics and machine learning components are integrated into a single **Streamlit web application**.


`round(...,2)` limits the result to two decimal places.

## A. Department Productivity Chart

```python
def hybrid_work_chart(df):

    department_chart = df.groupby(
        "Department"
    )["ProductivityScore"].mean().reset_index()
```

### What happens here?

Employees are grouped according to their department.

Then the average productivity score is calculated for each department.

For example:

```text
IT       → 82
HR       → 75
Finance  → 79
Sales    → 70
```

Then:

```python
fig = px.bar(
    department_chart,
    x="Department",
    y="ProductivityScore",
    color="Department"
)
```

creates a bar chart.

### Purpose

It helps compare productivity between departments.

# ⚠️ Important: Current Model Naming

Although the saved file is named:

```text
attrition_model.pkl
```

the current training code actually predicts:

```text
Performance_Category
```

not employee attrition.

Therefore, technically the current implementation should either:

### Option 1

Rename it to:

```text
performance_model.pkl
```

and use terminology such as:

```text
Performance Prediction
```

### OR

### Option 2 — Recommended

If your dataset contains an actual `Attrition` column, train the model using:

```python
y = df["Attrition"]
```

Then the model can genuinely be used for attrition prediction.

This distinction is important when presenting the project to recruiters.

# 14. Generating Predictions

Currently the application uses:

```python

    df[
        [
            "Training_Hours",
            "Engagement_Score",
            "Competency_Score"
        ]
    ]
)
```

`predict_proba()` returns the probability assigned to each class.

However, because the current model was trained on `Performance_Category`, these probabilities represent **performance-class probabilities**, not actual attrition probabilities.

Therefore, the current label:

```python

```

should be changed unless a genuine attrition model is trained.

# 16. `simulation.py` — Scenario Simulation

The simulation module allows users to interact with the application.

```python
meetings = st.slider(
    "Reduce Meetings (%)",
    0,
    50,
    10
)
```

The user can select a meeting reduction percentage.

Similarly:

```python
training = st.slider(
    "Increase Training Hours (%)",
    0,
    50,
    10
)
```

allows the user to increase training hours.

---

## Simulated Productivity

The application calculates:

```python
df["Simulated_Productivity"] = (
    df["ProductivityScore"]
    + (training * 0.1)
    - (meetings * 0.05)
)
```

The application then compares:

```text
Current Productivity
        vs
Simulated Productivity
```

using a line chart.

### Purpose

This provides a simple **what-if analysis**.

For example:

> "What would simulated productivity look like if training hours were increased?"

or:

> "What would simulated productivity look like under a different meeting scenario?"

### Important clarification

The simulation is based on **predefined assumptions**, not a machine-learning prediction.
